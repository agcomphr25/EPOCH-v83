Implement P1 OEM Packing Slip Invoice # Persistence + Searchability.

This is an implementation task, but proceed carefully and preserve existing behavior unless explicitly changed.

Context:
For now, the Invoice # printed on the P1 OEM packing slip is the official operational invoice identifier. It does not need to match a future preferred accounting format yet. Accounting can make QuickBooks match this number for now.

Primary goal:
The packing slip Invoice # must tie back to the shipment summary in /oem-shipments.

Do not redesign AR invoicing.
Do not change invoice numbering format yet.
Do not create QuickBooks integration.

==================================================
REQUIRED BUSINESS RULES
==================================================

1. The Invoice # generated for a P1 OEM packing slip must be stored on the shipment record.

2. Same shipment = same Invoice # forever.

3. Reprinting or regenerating a packing slip must reuse the existing stored Invoice #.

4. Regeneration must NOT call getNextInvoiceNumber() if the shipment already has an invoice_number.

5. /oem-shipments must display the Invoice # in the shipment summary/details.

6. /oem-shipments search must allow searching by Invoice #.

7. The packing slip PDF must continue to show the Invoice #.

8. Existing historical shipments may have NULL invoice_number until regenerated or manually handled. Do not attempt risky PDF parsing or historical backfill in this task.

==================================================
EXPECTED DATA MODEL
==================================================

Add a nullable invoice_number column to shipment_records.

Preferred column:
shipment_records.invoice_number text nullable

Reason:
Invoice # belongs to the shipment, not to individual shipment items.

Do not store invoice_number only on shipment_items unless the current schema absolutely requires it. If shipment_items must also reference it for compatibility, shipment_records remains the source of truth.
