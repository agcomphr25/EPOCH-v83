Root cause

Your “Production Timer” task is being created as:

taskType: 'PROCESS'

identifiable only by instructionPack.timerConfig

If your Timer Station UI is looking for something like taskType === 'TIMER' (or PROCESS_TIMER, etc.), it will never find the timer task, so it can’t start it reliably and/or can’t display the correct “model/program”.

That’s exactly the kind of “it’s not working properly” bug that feels random.

The clean fix (recommended): give Timer its own taskType
✅ Backend copy/paste patch (storage.ts)

Change your timer task creation to use a dedicated taskType.

Replace this block:

taskType: 'PROCESS',          // ← NOT 'TIMER' — it's 'PROCESS'


With this:

taskType: 'TIMER',


Full patch:

if (hasTimerConfig) {
  await this._createTaskIfAllowed({
    travelerStepId: step.id,
    taskType: 'TIMER', // ✅ dedicated type so the station can find it
    taskPhase: 'WORK',
    title: 'Production Timer',
    instructions: deptConfig.timerConfig.defaultProgramName
      ? `Start timer program: ${deptConfig.timerConfig.defaultProgramName}`
      : 'Start a production timer for this operation',
    required: false,
    sortOrder: sortOrder++,
    timePolicy: 'MANUAL_ENTRY',
    requiresSignature: false,
    requiresCertification: false,
    instructionPack: { timerConfig: deptConfig.timerConfig },
    status: 'NOT_STARTED',
  }, enabledPhases, createdTaskKeys);
}

Frontend patch: make the station find timer tasks reliably

You have two safe options:

Option A (best): Station finds taskType === 'TIMER'

Once you change backend to generate taskType: 'TIMER', update UI logic to use that.

Wherever you locate the timer task (likely something like):

const timerTask = tasks.find(t => t.taskType === 'TIMER');


If you don’t have that yet, add this helper in the Timer Station UI file:

function findTimerTask(tasks: TravelerTask[]) {
  return tasks.find(t => t.taskType === 'TIMER') ?? null;
}


And add an icon mapping so it renders nicely:

// wherever TASK_TYPE_ICONS lives
TASK_TYPE_ICONS['TIMER'] = Timer; // import Timer icon you already use, or lucide-react Timer

Option B (backward-compatible): Station finds either form

If you might have older travelers where timer is 'PROCESS' with timerConfig, make it robust:

function findTimerTask(tasks: TravelerTask[]) {
  return (
    tasks.find(t => t.taskType === 'TIMER') ??
    tasks.find(t => t.taskType === 'PROCESS' && !!t.instructionPack?.timerConfig) ??
    null
  );
}


That keeps old travelers working AND makes new ones clean.
