# Phase 4E — PDF Template Governance Architecture

**Status: DESIGN ONLY — NOT IMPLEMENTED**
**Date: February 26, 2026**

---

## Problem Statement

Sales Order PDFs are currently generated by `salesOrderPdf.ts` — a 1,300-line imperative drawing file using `pdf-lib` coordinate math. Layout changes require developer intervention, redeployment, and carry regression risk. There is no version history, no edit audit trail, and no way for operations staff to adjust wording, logos, or layout without code changes.

The goal: bring the same governance controls we built for email templates (versioning, role-gated editing, WYSIWYG editing, sanitization, audit logging) to the PDF generation system.

---

## Architectural Approach: HTML-to-PDF

**Render pipeline:**
```
HTML Template (governed, versioned, WYSIWYG-editable)
    ↓
Server-side interpolation (same {{variable}} engine as email)
    ↓
Puppeteer / Playwright headless Chrome
    ↓
PDF binary (stored on disk or returned as stream)
```

**Why HTML-to-PDF instead of continuing with pdf-lib:**
- The WYSIWYG editor (TipTap) already produces HTML — same tool, same training
- CSS handles layout (margins, tables, page breaks) without coordinate math
- Designers can iterate on templates without touching code
- `@page` CSS rules give precise control over paper size, margins, headers/footers
- The email template governance layer (sanitization, placeholder validation, versioning) transfers directly

**Rendering engine recommendation:** Puppeteer (headless Chromium) via `puppeteer-core` with a system-installed Chromium binary. Playwright is an alternative. Both support `page.pdf()` with full CSS print media support.

## Database Schema Design

### Table: `pdf_layout_templates`

The governed template store. Mirrors `email_templates` structure for consistency.

```sql
CREATE TABLE pdf_layout_templates (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  key             VARCHAR(255) NOT NULL UNIQUE,
  name            VARCHAR(255) NOT NULL,
  description     TEXT,

  -- Content
  body_html       TEXT NOT NULL,
  header_html     TEXT,
  footer_html     TEXT,

  -- Page configuration
  page_size       VARCHAR(20) NOT NULL DEFAULT 'LETTER',
  orientation     VARCHAR(20) NOT NULL DEFAULT 'portrait',
  margin_top      VARCHAR(20) NOT NULL DEFAULT '0.75in',
  margin_right    VARCHAR(20) NOT NULL DEFAULT '0.5in',
  margin_bottom   VARCHAR(20) NOT NULL DEFAULT '0.75in',
  margin_left     VARCHAR(20) NOT NULL DEFAULT '0.5in',

  -- Governance
  allowed_variables   JSONB NOT NULL DEFAULT '[]',
  current_version     INTEGER NOT NULL DEFAULT 1,
  is_active           BOOLEAN NOT NULL DEFAULT TRUE,

  -- Metadata
  template_type   VARCHAR(50) NOT NULL,
  updated_by      VARCHAR(255),
  created_at      TIMESTAMPTZ DEFAULT NOW(),
  updated_at      TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_pdf_layout_templates_type ON pdf_layout_templates(template_type);
CREATE INDEX idx_pdf_layout_templates_active ON pdf_layout_templates(is_active);
```

**`template_type` values:** `SALES_ORDER`, `INVOICE`, `PACKING_SLIP`, `PURCHASE_ORDER`, `RFQ`, `QUOTE`, `WORK_ORDER`, `CUSTOM`

**`page_size` values:** `LETTER` (8.5x11), `A4`, `LEGAL`, `HALF_LETTER`

### Table: `pdf_layout_template_versions`

Version history — identical pattern to `email_template_versions`.

```sql
CREATE TABLE pdf_layout_template_versions (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  template_id     UUID NOT NULL REFERENCES pdf_layout_templates(id),
  version         INTEGER NOT NULL,

  -- Snapshot of content at this version
  body_html       TEXT,
  header_html     TEXT,
  footer_html     TEXT,
  page_size       VARCHAR(20),
  orientation     VARCHAR(20),
  margin_top      VARCHAR(20),
  margin_right    VARCHAR(20),
  margin_bottom   VARCHAR(20),
  margin_left     VARCHAR(20),
  allowed_variables JSONB,

  -- Audit
  change_note     TEXT,
  created_by      VARCHAR(255),
  created_at      TIMESTAMPTZ DEFAULT NOW(),

  UNIQUE(template_id, version)
);
```

### Table: `pdf_layout_template_edit_logs`

Audit trail — identical pattern to `email_template_edit_logs`.

```sql
CREATE TABLE pdf_layout_template_edit_logs (
  id                UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  template_id       UUID NOT NULL REFERENCES pdf_layout_templates(id),
  edited_by         VARCHAR(255),
  previous_version  INTEGER NOT NULL,
  new_version       INTEGER NOT NULL,
  change_note       TEXT,
  edited_at         TIMESTAMPTZ DEFAULT NOW()
);
```

### Table: `generated_pdfs`

Rendered output log. Every PDF generation is recorded for traceability.

```sql
CREATE TABLE generated_pdfs (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  template_key    VARCHAR(255) NOT NULL,
  template_version INTEGER NOT NULL,
  entity_type     VARCHAR(50) NOT NULL,
  entity_id       VARCHAR(255) NOT NULL,
  file_path       TEXT NOT NULL,
  file_size       INTEGER,
  generated_by    VARCHAR(255),
  context_snapshot JSONB,
  generated_at    TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_generated_pdfs_entity ON generated_pdfs(entity_type, entity_id);
CREATE INDEX idx_generated_pdfs_template ON generated_pdfs(template_key);
```

## Rendering Service Design

### `server/services/pdfLayoutService.ts`

```
┌─────────────────────────────────────────────────────────────┐
│                    pdfLayoutService                          │
│                                                             │
│  renderPdf(templateKey, context, options?)                   │
│    1. Fetch template from pdf_layout_templates (by key)     │
│    2. Validate context against allowed_variables            │
│    3. Interpolate {{variables}} in body/header/footer HTML  │
│    4. Sanitize interpolated HTML (same sanitizer as email)  │
│    5. Wrap in full HTML document with @page CSS             │
│    6. Launch Puppeteer → page.setContent() → page.pdf()    │
│    7. Record in generated_pdfs table                        │
│    8. Return { buffer, filePath, templateVersion }          │
│                                                             │
│  renderPdfToFile(templateKey, context, outputPath)           │
│    → calls renderPdf, writes buffer to disk                 │
│                                                             │
│  renderPdfToStream(templateKey, context, res)                │
│    → calls renderPdf, pipes to HTTP response                │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### HTML Document Wrapper

The service wraps template HTML in a complete document with print-optimized CSS:

```html
<!DOCTYPE html>
<html>
<head>
  <meta charset="utf-8">
  <style>
    @page {
      size: ${pageSize} ${orientation};
      margin: ${marginTop} ${marginRight} ${marginBottom} ${marginLeft};
    }
    body {
      font-family: 'Helvetica Neue', Arial, sans-serif;
      font-size: 10pt;
      color: #000;
      -webkit-print-color-adjust: exact;
    }
    table { border-collapse: collapse; width: 100%; }
    .page-break { page-break-after: always; }
    /* Header/footer via running elements (Chromium supports) */
  </style>
</head>
<body>
  ${interpolatedBodyHtml}
</body>
</html>
```

### Puppeteer Management

```
┌──────────────────────────────────────┐
│         Browser Pool Manager          │
│                                      │
│  - Single shared Chromium instance   │
│  - Lazy initialization on first use  │
│  - Graceful shutdown on SIGTERM      │
│  - Page timeout: 30 seconds          │
│  - Max concurrent renders: 3         │
│  - Automatic restart on crash        │
└──────────────────────────────────────┘
```

## Migration Strategy: salesOrderPdf.ts → HTML Templates

### Phase 1: Parallel Operation
- Keep existing `salesOrderPdf.ts` (pdf-lib) as the default
- Create HTML template equivalents for Sales Order, Invoice, Packing Slip
- Add feature flag: `PDF_RENDER_ENGINE=legacy|html`
- Both paths produce identical output (validated visually)

### Phase 2: Switchover
- Default to HTML rendering
- Legacy path remains available via flag
- Monitor for regressions (file size, render time, visual fidelity)

### Phase 3: Deprecation
- Remove `salesOrderPdf.ts` and pdf-lib coordinate math
- All PDF generation flows through `pdfLayoutService`
- Existing `pdf_config_settings` values migrated to template CSS

## WYSIWYG Editor Integration

The existing TipTap editor at `/email-templates` extends to support PDF templates with additions:

### Editor Additions for PDF Mode
- **Page size selector** (Letter / A4 / Legal)
- **Orientation toggle** (Portrait / Landscape)
- **Margin controls** (top / right / bottom / left with inch/cm units)
- **Header/Footer HTML editors** (separate TipTap instances)
- **Page break insertion** button (inserts `<div class="page-break"></div>`)
- **Print preview** (renders via server and displays in iframe, not just HTML preview)

### Route: `/pdf-templates`

Separate page from email templates but shared governance components:
- Same version history panel
- Same variable sidebar
- Same capability enforcement (ADMIN/OWNER only)
- Additional page-layout controls

## API Routes

```
GET    /api/pdf-layout-templates              List all governed PDF templates
GET    /api/pdf-layout-templates/:key         Get single template
PUT    /api/pdf-layout-templates/:key         Update with versioning + sanitization
POST   /api/pdf-layout-templates/:key/preview Render preview PDF (returns PDF binary)
POST   /api/pdf-layout-templates/:key/validate Dry-run validation (placeholders, JS, length)
GET    /api/pdf-layout-templates/:key/versions Version history

POST   /api/pdf-render/:key                   Render a PDF with provided context data
```

All routes gated by `requireAdminRole` middleware (same as email templates).

## Risks and Mitigations

| Risk | Mitigation |
|---|---|
| Puppeteer memory usage on Replit | Browser pool with max 3 concurrent pages, auto-close idle pages |
| Chromium not available in Nix | Use `puppeteer` (bundles Chromium) instead of `puppeteer-core` |
| Visual fidelity vs pdf-lib output | Side-by-side regression testing before switchover |
| Large HTML templates causing slow renders | Same 500KB limit as email, render timeout of 30s |
| Signature embedding in HTML PDFs | Base64 image injection via `{{signature_block}}` variable |
| Page break control | CSS `page-break-after: always` class with editor button |
