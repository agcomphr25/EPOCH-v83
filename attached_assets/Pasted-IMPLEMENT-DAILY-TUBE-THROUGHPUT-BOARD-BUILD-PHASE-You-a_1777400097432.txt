Correct architecture:

Slot Creation:
traveler_steps.started_at
WHERE department_name = 'Layup'
AND started_at IS NOT NULL

Green Trigger:
traveler_steps.started_at
WHERE department_name = 'Oven/Cure'
AND started_at IS NOT NULL

Universal rule:
A slot is GREEN when that tube has entered Oven/Cure.

Business meaning:
GREEN = tube successfully completed pre-cure operations and entered the oven today.

Production sequence:
1. Mold Prep
2. Layup
3. Cello Wrap
4. Oven/Cure
5. Quality Control
6. Final QC

--------------------------------------------------
CORE REQUIREMENTS
--------------------------------------------------

Build a visibility-only board.

The board must:
- create fixed slots from actual Layup started events
- show 22 fixed daily slots
- keep Slot 1 as Slot 1, Slot 22 as Slot 22
- never compress or reorder slots
- show ghost slots for unstarted capacity
- show GREEN when Oven/Cure has started
- show BLOCKED / HOLD / VOID when applicable
- support TV mode and supervisor mode
- support historical date review
- auto-refresh in live mode
- perform no writes

The board must NOT:
- update travelers
- start or complete steps
- clear blocks
- approve anything
- reassign work
- mutate production data
- show customer/serial/SKU clutter on TV mode

--------------------------------------------------
BACKEND IMPLEMENTATION
--------------------------------------------------

Create a read-only endpoint:

GET /api/p2/daily-throughput-board?date=YYYY-MM-DD

If date is omitted:
use today in America/New_York business date.

Endpoint must return:

{
  businessDate,
  targetSlots: 22,
  summary,
  slots
}

Slot creation logic:

1. Find all traveler_steps where:
   department_name = 'Layup'
   started_at IS NOT NULL
   started_at falls within the selected business date
   using America/New_York timezone handling

2. Join to travelers.

3. Sort by Layup started_at ascending.

4. Assign slotNumber using sequence order.

5. Return slots 1–22 fixed.

6. If more than 22 were started, return overflow records with:
   isOverflow: true

Green logic:

For each traveler:
find traveler_steps where:
department_name = 'Oven/Cure'
AND started_at IS NOT NULL

If Oven/Cure started_at exists:
isGreen = true
greenAt = Oven/Cure started_at

Status priority:

Use this order:

1. CANCELLED / VOID
   - traveler.status = 'CANCELED' or equivalent

2. BLOCKED
   - travelers.status = 'BLOCKED'
   - OR current/relevant traveler_steps.status = 'BLOCKED'

3. HOLD
   - if a hold state exists in current traveler model

4. REWORK
   - if existing rework/NCR state is detectable without new workflow

5. GREEN
   - Oven/Cure started

6. LATE
   - only if simple threshold exists safely
   - if not, omit LATE from Phase 1

7. IN_PROCESS

8. NOT_STARTED

Do not invent new data.

If hold/rework sources are unclear, include null-safe placeholders and document them.

Summary counts:
- targetSlots
- started
- green
- inProcess
- blocked
- cancelled
- notStarted
- overflowCount

No projected EOD in Phase 1.
