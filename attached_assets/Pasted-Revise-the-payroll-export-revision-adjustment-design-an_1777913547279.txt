Context:
We are designing a DCAA-oriented Gusto CSV payroll export model.

Policy decisions:
- Payroll export is Gusto CSV only.
- Payroll processing confirmation is manual/human-entered.
- Only OWNER/ADMIN can create exports, supersede exports, void exports, or mark payroll as processed.
- Exports are full-period only for regular payroll.
- Multiple full exports for the same pay period are allowed before payroll is processed.
- Each subsequent full export for the same pay period creates a new revision batch.
- The previous active unprocessed full-period export is marked superseded.
- Exact CSV contents and checksums must be preserved for every export.
- Re-download must return the exact stored CSV/rows, not freshly recalculated data.
- Once a batch is marked processed, it is immutable historical evidence.
- Corrections after processing should create payroll adjustments for a future payroll run, not alter the processed batch.
- Admin can choose whether approved adjustments are included in the next regular payroll export or in a separate off-cycle correction export.
- If a correction/time edit is attempted after a pay period has an active unprocessed export, the edit should be blocked until OWNER/ADMIN explicitly supersedes or voids the active export with a reason.
