Copy-Paste Implementation Prompt (Safe Structural Fix)
This is a SURGICAL IMPLEMENTATION TASK.

Goal:
Separate the sequence counters used by P1 customer orders and P2 production orders so they never share the same counter again.

Currently both systems use the same table:

order_id_sequences

This caused FC customer orders to jump from FC062 → FC1290 when a large P2 batch finalized.

We will introduce a dedicated sequence table for P2 production orders and update the P2 generator to use it.

IMPORTANT RULES

1) Do NOT modify existing customer order numbering.
2) Do NOT rename any existing order IDs.
3) Do NOT reset order_id_sequences.
4) Only modify the P2 generation logic.
5) Historical data must remain valid.

--------------------------------------------------
STEP 1 — CREATE NEW SEQUENCE TABLE
--------------------------------------------------

Add a new table to server/schema.ts.

Name:

p2_order_id_sequences

Schema:

- year_month_prefix TEXT PRIMARY KEY
- current_sequence INTEGER NOT NULL DEFAULT 0
- updated_at TIMESTAMP

Example structure:

p2_order_id_sequences
---------------------
year_month_prefix TEXT (PK)
current_sequence INTEGER
updated_at TIMESTAMP

This table will track sequences ONLY for P2 production orders.

--------------------------------------------------
STEP 2 — CREATE P2 GENERATOR FUNCTION
--------------------------------------------------

In server/storage.ts create a new function:

generateNextP2OrderIds(prefix: string, count: number)

Behavior:

1) Use an atomic UPSERT exactly like the existing generator
2) Increment by the batch size
3) Return the starting and ending sequence numbers

Pseudo logic:

INSERT INTO p2_order_id_sequences (year_month_prefix, current_sequence)
VALUES (prefix, count)
ON CONFLICT (year_month_prefix)
DO UPDATE SET
  current_sequence = p2_order_id_sequences.current_sequence + count
RETURNING current_sequence

Compute:

startSequence = returnedSequence - count + 1
endSequence = returnedSequence

Return both values.

--------------------------------------------------
STEP 3 — UPDATE P2 FINALIZATION LOGIC
--------------------------------------------------

Locate the batch code inside:

server/storage.ts

Function:

finalizeP2PurchaseOrder()

Currently this section reserves order numbers using:

order_id_sequences

Replace ONLY this portion to call:

generateNextP2OrderIds()

Example flow:

prefix = getCurrentYearMonthPrefix(now)

const { startSequence, endSequence } =
    await generateNextP2OrderIds(prefix, pendingOrders.length)

Then assign IDs:

prefix + padded(sequence)

Example:

FC002
FC003

But generated from the P2 table.
