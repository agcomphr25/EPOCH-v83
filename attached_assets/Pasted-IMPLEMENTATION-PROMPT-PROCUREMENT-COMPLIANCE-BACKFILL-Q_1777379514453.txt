OBJECTIVE
==================================================

Current state:

The Procurement ERDI scorer is now truthful.

- no compliance review exists
- FAR applicability undocumented
- FAR statement missing
- second-party approval unknown
- vendor approval unknown
- stale reviews
- missing justification notes

This is correct.

We now need a controlled way for Inventory / Procurement to work through those historical records.

Build:

PROCUREMENT COMPLIANCE BACKFILL QUEUE

==================================================
PRIMARY UX GOAL
==================================================

Allow inventory manager to answer:

“Which POs are hurting our ERDI score right now, and what exactly must be fixed?”

This must be obvious.

Actionable.

Not detective work.

==================================================
PART A — BACKFILL QUEUE PAGE
==================================================

Create:

Procurement → Compliance Backfill Queue

or appropriate admin/compliance location.

Display a queue/table of Vendor POs requiring compliance remediation.

Include:

- PO Number
- Vendor
- Issue Date
- Current Status
- Compliance Status
- FAR Status
- Missing Review?
- Missing FAR Statement?
- Missing Second-Party Approval?
- Missing Vendor Approval?
- Missing Justification Notes?
- Requires Attention?
- Review Age / Stale Review
- Priority Score
- Recommended Action

This should be sortable/filterable.

==================================================
PART B — PRIORITY SCORING
==================================================

Prioritize work intelligently.

Suggested priority:

CRITICAL:
- issued PO
- no compliance review exists
- FAR likely required but missing
- vendor_approved false on issued PO

HIGH:
- requires_attention
- stale reviewed PO
- FAR required but statement missing

MEDIUM:
- FAR marked not required but notes missing
- second-party incomplete on pending PO

LOW:
- older closed PO with partial documentation gaps

Do not over-engineer.
A simple deterministic priority score is enough.

==================================================
PART C — “WHY THIS IS FAILING” PANEL
==================================================

Each queue row must clearly show:

WHY this PO is hurting compliance.

Example:

PO-1042

Failing Because:
- No compliance review exists
- Government contract likely indicated by prior FAR statement usage
- FAR/DFARS statement missing
- No second-party approval captured

Recommended Fix:
→ Complete Compliance Review
→ Confirm FAR applicability
→ Attach FAR/DFARS statement
→ Re-issue if required by policy

This is critical.

No mystery.

==================================================

directly from queue

Do NOT allow silent “Mark Complete”

Real review only.
