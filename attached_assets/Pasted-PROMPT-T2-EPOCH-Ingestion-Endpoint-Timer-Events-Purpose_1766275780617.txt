PROMPT T2 — EPOCH Ingestion Endpoint (Timer Events)

Purpose:
Create a minimal, optional ingestion endpoint in EPOCH to accept process-run events from the Timer app, without impacting existing workflows or requiring the Timer to be active.

🔷 COPY EVERYTHING BELOW INTO REPLIT AGENT
You are modifying an existing production app (EPOCH).

GOAL
Add a simple, optional ingestion endpoint so EPOCH can receive process-run events from an external Timer / Process Runner app.

This endpoint must be safe, ignorable, and non-disruptive.

---

REQUIREMENTS

1) BACKEND — Integration Endpoint
Create a new endpoint:

POST /api/integrations/process-runner/events

This endpoint should:
- Accept JSON payloads from an external app
- Validate required fields lightly
- Persist the event data
- Return 200 OK on success

Do NOT:
- Trigger scheduling changes
- Update orders automatically
- Modify labor, costs, or inventory
- Block requests if Timer is offline

---

2) EVENT PAYLOAD (MINIMAL CONTRACT)
Expect payloads shaped roughly like:

- source: "process_runner"
- programRunId (string or number)
- programName (string)
- eventType ("program_started" | "step_advanced" | "program_completed")
- timestamp (ISO string)
- stepIndex (number, optional)
- totalElapsedMinutes (number, optional)
- metadata (JSON, optional)

Rules:
- Ignore unknown fields
- Do not enforce strict schemas
- Store raw payload for future use

---

3) DATA STORAGE
Persist received events in a simple table or existing event log.

Requirements:
- Store raw payload
- Store receivedAt timestamp
- Store source identifier

If an existing generic events table exists, reuse it.
If not, create the smallest possible table.

---

4) IDEMPOTENCY & SAFETY
- If the same event is received twice, it should not crash
- Deduplication is NOT required at this stage
- Logging is acceptable but should be minimal

---

5) AUTHENTICATION (LIGHT)
- Protect the endpoint with a simple shared secret or token
- Token can be environment-based
- Do NOT introduce OAuth or complex auth flows

---

6) NON-GOALS (DO NOT DO THESE)
- No UI changes
- No dashboards
- No analytics
- No job linking
- No notifications
- No Donna integration

This endpoint exists even if nothing uses it.

---

7) ACCEPTANCE CRITERIA
- Endpoint exists and accepts requests
- EPOCH functions identically if no events are sent
- Timer app can POST events without errors
- No regressions in existing EPOCH functionality

Proceed with the smallest, safest implementation that creates a clean ingestion seam.
