## 🎯 OBJECTIVE

Implement allocation switching so that:

- When a traveler starts OR a job switch occurs:
  → current allocation is CLOSED
  → new allocation is OPENED

This preserves full job history within a single punch session.

## 🔍 STEP 1 — IMPLEMENT switchAllocation

In:

server/src/services/laborAllocationService.ts

Replace the stub with real logic:

### switchAllocation(punchLedgerRow, newAssignment)

Steps:

1) Find current OPEN allocation:
   - punch_ledger_id = row.id
   - status = 'OPEN'

2) IF no open allocation:
   - log warning
   - call openAllocation() with newAssignment
   - return

3) IF open allocation exists:

   a) Close current allocation:
      - allocation_end = now()
      - status = 'CLOSED'

   b) Determine next sequence_order:
      - count existing allocations for this punch_ledger_id
      - next = count + 1

   c) Create new allocation:
      - punch_ledger_id
      - employee_id
      - allocation_start = now()
      - allocation_end = NULL
      - charge_code_id (from newAssignment)
      - traveler_id
      - traveler_step_id
      - production_work_order_id
      - project_id
      - department
      - operation
      - labor_class (carry forward or from assignment)
      - source = 'TRAVELER'
      - status = 'OPEN'
      - sequence_order = next

4) Wrap entire operation in try/catch:
   - log errors
   - NEVER throw
