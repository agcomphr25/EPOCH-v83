Implement Capability-Based Permission System
TASK: Implement a capability-based permission system for EPOCH while preserving the existing route permission logic.

GOAL
Replace route-only permissions with a scalable capability system that supports:

• Role-based permissions
• Per-user overrides
• Page protection
• Button/action protection
• Future field-level permissions
• API enforcement

Do NOT break existing functionality. This should be additive.

BACKEND IMPLEMENTATION

Create middleware:

server/middleware/requirePermission.ts

Function:

requirePermission(permissionKey)

Behavior:

1. Load user role permissions
2. Apply user overrides
3. Deny if permission not present
4. Return 403 if unauthorized

Example:

app.post(
  "/api/invoices/delete",
  requirePermission("finance.invoice.delete"),
  deleteInvoiceHandler
)

----------------------------------------------------

PERMISSION RESOLUTION LOGIC

Final permissions are computed as:

(role permissions)
+ user allow overrides
- user deny overrides

Implement helper:

getUserPermissions(userId)

Cache results in memory for the request lifecycle.

----------------------------------------------------

FRONTEND IMPLEMENTATION

Create hook:

client/hooks/usePermissions.ts

Functions:

can(permissionKey)

Example usage:

if (!can("finance.invoice.view")) redirect("/")

Buttons:

{can("finance.invoice.delete") && <DeleteButton />}

Add permission metadata to protected pages.

ADMIN UI

Add admin page:

Settings → Roles & Permissions

Admins can:

MIGRATION STRATEGY

Map current route permissions to capabilities.

Example:

/finance/invoices → finance.invoice.view
/finance/ar → finance.ar.view

Do not delete route permissions yet.

Route checks should fallback to capability checks.
