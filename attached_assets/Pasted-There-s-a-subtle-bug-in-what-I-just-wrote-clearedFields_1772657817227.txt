Three changes made and why:

isTikkaModel from model.id — selectedModel?.id.toLowerCase().includes('tikka') instead of reading displayName/name. Model IDs (alpine_hunter_tikka, cf_visigoth_tikka, privateer-tikka, etc.) are stable data-layer identifiers. Display names can be edited in the admin UI without breaking the rule.

features.barrel_inlet removed from deps — the effect no longer fires when the user picks a barrel option. All three features.* deps are removed (not just barrel_inlet) so the effect exclusively fires on modelId changes, which is what requirement 3 requires.

eslint-disable comment — added because intentionally omitting features.* from the dep array will trigger the exhaustive-deps lint rule. The comment makes the intent explicit rather than appearing to be an oversight.

Intentional behaviour change: If the user is on a Tikka model and somehow lands a non-Tikka barrel_inlet in state (e.g., via programmatic duplicate), the clearing will not fire until the model is changed. The dropdown filter (which hides non-Tikka options for Tikka models visually) still prevents accidental selection through normal UI interaction.
