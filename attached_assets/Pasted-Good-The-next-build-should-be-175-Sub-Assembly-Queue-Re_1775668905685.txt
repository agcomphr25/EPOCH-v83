#175 — Sub-Assembly Queue Readiness Page

This is where the system starts coordinating parts together instead of just checking raw materials.

What & Why

Add a /sub-assembly-queue page that mirrors Kits/Layup/Core but targets queueType=SUB_ASSEMBLY items.

Sub-Assembly is where completed components, kits, and consumables must all be ready before controlled build-up can begin. This page gives planners and operators a single place to see whether a sub-assembly can actually start, what is missing, and whether it is ready to release.

Done looks like
Navigating to /sub-assembly-queue shows a filterable table of all SUB_ASSEMBLY queue items
Each row displays:
readiness badge (NOT_READY / PARTIAL / READY / BLOCKED)
percent-ready
blocked reason summary
Clicking a row opens the shared RequirementDrawer
The drawer shows requirement lines for:
child components
required kits
consumables
other dependency types already generated into allocation_requirements
A SUB_ASSEMBLY item can be released only when readinessStatus = READY
The page is registered in App.tsx and reachable from the sidebar/nav alongside Core Queue
Out of scope
New demand generation rules for sub-assemblies
Traveler execution UI changes
New dependency schema changes
Automatic completion rollups from child travelers
