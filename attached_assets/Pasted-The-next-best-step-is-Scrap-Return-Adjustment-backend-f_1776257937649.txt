#272 - Scrap Route Backend Hardening

What & Why
Add a controlled scrap route for material lots so unusable, damaged, contaminated, or expired material can be permanently removed from stock with a reasoned audit trail. Without this, operators or admins may rely on manual quantity edits, which weakens traceability and causes balance drift.

Done looks like

POST /api/material-lots/:id/scrap exists
Requires qty, reason, and performedBy
Blocks scrap if qty is greater than lot remainingQty
Blocks scrap on lots already fully consumed
Updates material_lots.remainingQty
Sets lot status to SCRAPPED if remaining reaches zero; otherwise leaves status usable or moves to partial-scrap logic per current rule
Writes material_lot_transactions with transactionType='SCRAP'
Writes inventory_transactions
Updates inventory_balances.quantityOnHand
Recomputes quantityAvailable = quantityOnHand - quantityAllocated
All writes happen in one transaction
