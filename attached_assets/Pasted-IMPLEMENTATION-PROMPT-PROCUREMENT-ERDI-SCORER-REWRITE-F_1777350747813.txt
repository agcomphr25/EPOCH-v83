PHASE 2 — SCORING MODEL DESIGN
==================================================

Design a scoring model based on real evidence.

Required principles:

1. Score only what the system can prove.
2. Distinguish “not applicable” from “missing.”
3. Do not punish non-government POs for not having FAR.
4. Do not reward POs where FAR is selected but no compliance review exists.
5. Do not reward stale reviews marked requires_attention.
6. Do not rely on free-text vendor terms/notes.
7. Prefer issued/sent POs as primary evidence.
8. Include pending/open POs as risk indicators where appropriate.

==================================================
FAR_FLOWDOWN SCORING REQUIREMENTS
==================================================

Rewrite FAR_FLOWDOWN to evaluate actual PO compliance.

Suggested logic:

Population:

Vendor POs that are issued/sent/active within the scorer’s intended scope.

Evidence fields:

- compliance review exists
- review_status = reviewed
- far_required = true/false
- review_notes present
- reviewed_at present
- if far_required = true:
  - FAR/DFARS optional statement is attached to PO
  - issue gate was satisfied
- if far_required = false:
  - review exists with documented notes explaining decision

Scoring:

FULL if:

- reviewed issued POs have documented FAR applicability decisions
- all FAR-required POs have FAR/DFARS statement attached
- no issued PO has stale/requires_attention compliance review

PARTIAL if:

- some issued POs have compliance reviews
- but some are missing review, missing notes, missing FAR statement, or stale

FAIL if:

- issued POs exist but no compliance review evidence exists
- FAR-required POs lack FAR statement
- issued POs are requires_attention or blocked

N/A if:

- no issued vendor POs exist in scope

Evidence output must include:

- total issued POs reviewed
- number with compliance review
- number FAR required
- number FAR required with statement attached
- number FAR marked not required with notes
- number stale/requires_attention
- sample failing PO ids/numbers
