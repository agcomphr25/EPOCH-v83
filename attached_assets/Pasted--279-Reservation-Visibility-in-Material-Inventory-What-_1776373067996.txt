#279 — Reservation Visibility in Material Inventory
What & Why

Right now your system enforces reservations in the backend (consume logic), but operators cannot see them in the UI.

That creates a gap:

System says ❌ “OVER_COMMITTED”
Operator says 🤨 “but it shows quantity available”

👉 This ticket closes that gap.

You make reservations visible, understandable, and actionable.

Done looks like

On the Material Inventory page:

Each lot shows:
Remaining Qty
Reserved Qty
Available Qty (Remaining - Reserved)
UI behavior:
Reserved quantity is clearly labeled
Available quantity is clearly labeled
If reserved > 0 → visual indicator
If fully reserved → show warning badge
Optional (but recommended):
Hover or click shows:
which traveler / work order reserved it
how much each reserved
Why this matters

This directly supports:

your consume route hardening
your reservation logic
your AS9100 traceability model

Without this, operators:

don’t understand why they’re blocked
may try to work around the system

With this:

they trust the system
they plan around reservations
Backend (light work)
Add to existing lot response:

You likely already have:

getLotReservations(lotId)
getReservedQtyForLot(lotId)

👉 Extend your lot list endpoint (GET /api/material-lots) to include:

reservedQty: number
availableQty: number

Where:

reservedQty = SUM(active reservations)
availableQty = remainingQty - reservedQty
Optional (Phase 2 detail)
reservations: [
  {
    travelerId,
    workOrderId,
    quantityReserved
  }
]
Frontend Tasks
File:

client/src/pages/MaterialInventoryPage.tsx

1. Extend MaterialLot interface

Add:

reservedQty?: number;
availableQty?: number;
2. Update Quantity column
Replace this:
{lot.remainingQty} / {lot.receivedQty} {lot.unitOfMeasure}
With this:
<div className="space-y-1 text-sm">
  <div>
    <span className="font-medium">
      {lot.remainingQty} {lot.unitOfMeasure}
    </span>
    <span className="text-muted-foreground ml-1">
      / {lot.receivedQty}
    </span>
  </div>

  <div className="text-xs text-muted-foreground">
    Reserved: {lot.reservedQty ?? 0}
  </div>

  <div className="text-xs">
    Available:{' '}
    <span className="font-medium">
      {lot.availableQty ?? lot.remainingQty}
    </span>
  </div>
</div>
3. Add visual indicator in Alerts column

Add this inside Alerts section:

{(lot.reservedQty ?? 0) > 0 && (
  <Badge variant="outline" className="text-xs">
    Reserved
  </Badge>
)}

{(lot.availableQty ?? Number(lot.remainingQty)) <= 0 && (
  <Badge variant="destructive" className="text-xs">
    Fully Reserved
  </Badge>
)}
4. Optional (strong UX improvement)
Tooltip or hover breakdown

Add later:

show:
Traveler ID
Reserved qty

Example:

Reserved:
- TRV-001 → 5
- TRV-002 → 3
5. No changes needed to:
dropdown actions
scrap
consume
history dialog

This is purely visibility layer

UI Result

Before:

Qty: 20 / 50

After:

20 / 50
Reserved: 12
Available: 8
[Reserved badge]
Edge Cases

Handle:

no reservations → show 0
missing backend fields → fallback to remainingQty
negative available → clamp to 0 (UI only)
Out of scope
editing reservations
creating reservations
reservation UI workflows
allocation controls
