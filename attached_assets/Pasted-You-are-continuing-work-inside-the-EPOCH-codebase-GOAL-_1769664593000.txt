GOAL:
Implement Phase 2A of the Employee Onboarding System:
Generate a canonical, immutable onboarding PDF bundle
from a COMPLETED onboarding session.

---

CORE PRINCIPLES:
• Bundle generation is READ-ONLY
• Signed PDFs are NEVER altered
• Bundle represents a point-in-time record
• Bundle is reproducible only by reference, not re-signing

---

SCOPE (STRICT):

1) BUNDLE GENERATION SERVICE

Create:
server/src/services/onboardingPdfBundleService.ts

Function:
generateOnboardingBundle(sessionId)

Behavior:
• Session must exist
• Session must be status = 'completed'
• No database writes to onboarding or employees

---

2) BUNDLE CONTENT (IN THIS ORDER)

Page 1 — Cover Page
• Employee legal name
• Employment type
• Job title
• Hire date
• Onboarding completed timestamp
• Admin who finalized
• EPOCH logo / branding

Page 2 — Intake Summary
• Read-only rendering of intakeData
• Field labels + values
• Exclude internal-only fields

Page 3+ — Signed Documents
• Append each signedPdfPath
• Preserve original order
• No modification of signatures

Next — Captured Images
• Driver license photo(s)
• Employee photo(s)
• Rendered cleanly on individual pages

Final Page — Audit Summary
• Document names
• Signed timestamps
• IP addresses
• Finalization timestamp

---

3) PDF IMPLEMENTATION DETAILS

• Use pdf-lib (already used elsewhere if available)
• DO NOT rasterize signed PDFs
• Append PDFs using page copying
• Images scaled proportionally
• Ensure output is printable and archival-quality

• As a Media Library item
• Category: onboarding_bundle
• Linked to employeeId
• Immutable (no overwrite)
