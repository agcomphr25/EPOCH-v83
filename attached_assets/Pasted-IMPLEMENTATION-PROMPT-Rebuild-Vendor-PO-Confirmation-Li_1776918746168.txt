Root cause is confirmed:

The current system consumes the vendor confirmation token on first GET request inside:

GET /api/magic-link/verify

which calls:

validateMagicLink()
→ markMagicLinkTokenAsUsed()

This causes:
- Microsoft Safe Links
- Proofpoint
- Mimecast

- browser preloading

to consume the token before the vendor ever clicks it.

Vendors then receive:
“Link Expired or Invalid”

This is not acceptable.

We must rebuild this architecture correctly.
