LABOR CAPTURE ASSISTANT BACKEND SUGGESTION ENGINE

Backend only.
No frontend.
No accept/apply workflow.
No posting to salaried_timesheet_lines.
No DONNA.

Core rule:
AI Suggests
Human Approves
System Audits

==================================================
OBJECTIVE
==================================================

Implement backend-only natural language labor suggestion infrastructure.

The system should accept an employee narrative, generate validated draft labor suggestions, persist those suggestions for audit, and allow rejection.

It must NOT create actual timesheet lines yet.

==================================================

==================================================
AI CONTEXT LIMITS
==================================================

Allowed prompt context only:

- employee identity
- employee department, if already available
- employee’s likely travelers from existing logic
- active indirect code catalog

Do NOT include:
- salary data
- payroll rates
- GL balances
- other employees
- unrestricted project database dump
- company-wide financials

Keep the context narrow.

==================================================
VALIDATION ENGINE
==================================================

Every AI suggestion must be validated server-side before being persisted.

DIRECT LABOR validation:
- match AI travelerHint only against allowed likely travelers / DB-confirmed candidates
- traveler must exist
- traveler must be active / valid for labor
- resolveChargeCode() must succeed
- resolvedFrom must not be "none"
- project mapping must exist
- if uncertain, mark ambiguous; do not assign random traveler

INDIRECT LABOR validation:
- indirectCodeHint must map to active indirect code
- indirect code must have valid charge_code_id
- no fallback to UNALLOC
- if uncertain, mark ambiguous

Hours validation:
- individual line hours > 0
- no negative hours
- total suggested hours for a day <= 24

Timesheet validation:
- timesheet must belong to employee
- timesheet must be editable
- no suggestions for submitted / approved / locked timesheets

Confidence rules:
- green: confidence >= 0.85
- amber: confidence >= 0.70 and < 0.85
- red: confidence < 0.70

Red suggestions:
- must be marked manual clarification required
- must not be considered ready-to-accept in future workflow

==================================================
SECURITY REQUIREMENTS
==================================================

Implement:
- narrative length cap: 2,000 characters
- strip / reject HTML and script-like content
- prompt injection resistant system prompt
- no raw prompt leakage in API responses
- no unsafe logging of employee narrative
- expire stale DRAFT suggestions
- reject access to other employees’ suggestions
- reject expired suggestions from retrieval or clearly mark them expired
