Implement inline credential-gated actions for the Timer Station.

GOAL:
Allow anyone to view the Timer Station without logging in,
but require valid user credentials to perform any state-changing action,
using an inline modal instead of redirecting to the login page.

────────────────────────────────────────
PART 1 — PUBLIC VIEW ACCESS
────────────────────────────────────────

1) MAKE TIMER STATION VIEW PUBLIC
- Allow unauthenticated users to access:
    /app/production/stations
- Read-only data must be visible:
    - active timers
    - program names
    - elapsed / remaining time
    - status indicators

- Do NOT allow:
    - starting timers
    - stopping timers
    - pausing/resuming
    - modifying programs
    - administrative actions

────────────────────────────────────────
PART 2 — INLINE CREDENTIAL CHALLENGE
────────────────────────────────────────

2) ADD INLINE AUTH MODAL
Create a reusable modal component:
- Fields:
    - username
    - password
- No navigation
- No page reload
- Closes on success

This modal is triggered when:
- An unauthenticated user attempts a restricted action

────────────────────────────────────────
PART 3 — ACTION GUARDING (FRONTEND)
────────────────────────────────────────

3) GUARD ALL MUTATING ACTIONS
For each Timer Station action:
- Start timer
- Stop timer
- Pause timer
- Resume timer
- Any button that changes state

If user is not authenticated:
- Prevent action
- Open credential modal

If authenticated:
- Proceed normally

────────────────────────────────────────
PART 4 — ACTION GUARDING (BACKEND)
────────────────────────────────────────

4) ADD CREDENTIAL VALIDATION ENDPOINT
Add endpoint:
POST /api/auth/validate-credentials

Input:
{
  username,
  password
}

Behavior:
- Validate credentials using existing auth logic
- Do NOT create a full login session
- Return a short-lived action token (e.g. 5–15 minutes)
  OR mark request context as authenticated for this session

────────────────────────────────────────
PART 5 — TEMPORARY ACTION AUTHORIZATION
────────────────────────────────────────

5) ACTION TOKEN HANDLING
After successful credential validation:
- Store temporary authorization in memory or session storage
- Attach token to subsequent mutating requests
- Token expires automatically

This allows:
- Multiple actions without repeated prompts
- No full login redirect
- No persistent login state

────────────────────────────────────────
PART 6 — AUDIT LOGGING
────────────────────────────────────────

6) LOG CREDENTIAL-GATED ACTIONS
For every successful action:
- Log via auditService.logEvent
- Include:
    - actor (user)
    - action performed
    - source = 'timer_station'
    - authMethod = 'inline_credentials'

For failed credential attempts:
- Log failed validation (rate-limited)

────────────────────────────────────────
PART 7 — UX SAFETY
────────────────────────────────────────

7) UX RULES
- Never redirect to /login from Timer Station
- Never block read-only viewing
- Never store plaintext credentials
- Never persist auth beyond short TTL
- Show clear error messages on failure

────────────────────────────────────────
DELIVERABLES
