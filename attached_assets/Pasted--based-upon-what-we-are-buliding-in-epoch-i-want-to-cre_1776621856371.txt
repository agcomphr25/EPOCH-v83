D. Budget consumption logic
Best practice:

Allocated = committed against project budget

Issued to traveler = moved from available to in-use

Consumed = actual cost burned

Scrapped = separate bucket visible to PM

Returned to stock = reverses unused issue

That way PM sees real budget movement, not just inventory on hand.

How live time allocation should work
You said:

live feed of how the time is being allocated through the traveler

That is exactly right.

The cleanest method is:

When an employee starts work on a traveler step:

traveler step knows department/task

work order knows project

WAD rule resolves correct charge code

time clock entry begins automatically or is linked

PM dashboard updates live

So the feed row becomes:

Employee: John Smith

Project: Drone Wing Program

Work Order: WO-1028

Traveler: TRV-4401

Department: Layup

Task: Skin layup

Charge Code: DL-LAYUP-001

Started: 8:14 AM

Elapsed: 01:27

Certification: Valid

That is far better than manual PM entry.

Strong business rules to define now
Before building, lock these rules:

Labor
can labor exceed WAD hours automatically or require approval?

are employees blocked from charging if no hours remain?

can PM see pending overrun requests?

are only certified employees allowed, or do you allow warning-only mode?

Material
does allocation reserve material against the project budget immediately?

is budget consumed at allocation, issue, or actual consumption?

how is scrap treated?

do returned materials restore budget?

Production
is progress based on traveler completion, work order completion, or quantity complete?

what counts as “blocked”?

what triggers “at risk”?

These rules will make or break the dashboard usefulness.
