Prompt 1 — Implement Unit Families System (Safe Migration)
Writing

You are implementing a Unit Families system for EPOCH to prevent invalid unit conversions and simplify inventory item configuration.

This must be implemented as a safe additive change that does NOT break existing data or inventory logic.

This is a full implementation task. Follow the instructions exactly.

OBJECTIVE

Create a Unit Family architecture so that unit conversions only occur within the same measurement family.

Example families:

mass
volume
length
count
area

This prevents invalid conversions such as:

lb → meter
g → gallon

Only conversions within the same family are allowed.

SECTION 1 — DATABASE SCHEMA

Create two new tables.

unit_families

columns:

id uuid primary key default gen_random_uuid()
name text not null unique
created_at timestamp default now()

Example rows:

mass
volume
length
count
area

units

columns:

id uuid primary key default gen_random_uuid()
symbol text not null unique
family_id uuid not null references unit_families(id)
conversion_to_base numeric not null
created_at timestamp default now()

conversion_to_base definition:

This represents conversion to the base unit of the family.

Example for MASS:

g = 1
kg = 1000
lb = 453.592
oz = 28.3495

Example for LENGTH:

m = 1
cm = 0.01
ft = 0.3048
in = 0.0254

SECTION 5 — VALIDATION RULE

Add server validation:

purchase_unit.family_id MUST equal usage_unit.family_id

If mismatch:

throw error:

"Purchase unit and usage unit must belong to the same measurement family."

SECTION 6 — CONVERSION SERVICE

Create a shared utility:

server/src/utils/unitConversionService.ts

Function:

convertUnits(
value: number,
fromUnitId: string,
toUnitId: string
)

Steps:

fetch both units

confirm same family_id

convert using conversion_to_base

formula:

value_in_base = value * from.conversion_to_base
result = value_in_base / to.conversion_to_base
