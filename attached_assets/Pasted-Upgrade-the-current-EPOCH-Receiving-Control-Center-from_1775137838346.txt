Main objective
Make receiving the controlled traceability entry point for material in EPOCH.

That means:
- shipment-level receiving
- required document enforcement
- disposition-based usability rules
- expiration enforcement
- reservation vs available logic
- traveler scan traceability enforcement
- lot genealogy support
- better batch receiving UX

Tasks

1. Add shipment-level receipt fields
Update receipts so a receipt clearly represents a physical shipment event.

Add if missing:
- packingSlipNumber
- carrier
- trackingNumber
- shipmentCondition
- receivedBy
- receivedAt
- shipmentNotes

Update:
- schema
- validation
- routes
- UI forms
- receipt detail views

2. Add required receiving document rules
At the inventory item level, add if missing:
- requiresSDS
- requiresTDS
- requiresCoC
- requiresTestReport
- requiresPackingSlipPhoto

Then enforce server-side:
- if user tries to mark a unit or receipt as Accepted and required docs are missing, reject with 422
- return a clear missing-doc list
- show that missing-doc list in the UI

3. Enforce disposition-based usability
Only ACCEPTED material should be usable.

Server-side rules:
- pending inspection cannot be reserved or issued
- quarantined cannot be reserved or issued
- rejected cannot be reserved or issued
- only accepted material appears as available for production/travelers

Update inventory availability logic accordingly.

4. Add expiration and shelf-life enforcement
Use received unit expiration fields and/or linked lot data.

Implement:
- expired material cannot be reserved, issued, or scanned into a traveler
- near-expiration warning state
- clear UI statuses:
  - active
  - near expiration
  - expired
- endpoint or query support for expiring-soon material

5. Clean up reservation vs available logic
Support:
- onHandQuantity
- reservedQuantity
- availableQuantity

Do not allow over-reservation.
Make sure availability calculations use accepted, non-expired material only.

6. Add traveler integration path
Analyze the existing traveler material traceability scan flow and integrate received_units/material-lot validation into it.

Goal:
A traveler material scan should only succeed when the unit is:
- accepted
- not expired
- not quarantined
- not rejected
- has quantity available if quantity-based

Traveler scan should fail closed otherwise.

7. Add genealogy support
Support traceability queries for:
- which receipt a unit came from
- which PO line it came from
- which work order/traveler used it
- which lots/units were used in a completed assembly

At minimum add backend query support and route structure for:
- receipt -> received unit -> allocation/transaction -> traveler/work order usage
- reverse lookup from unit/lot to usage

8. Improve batch receiving UX
Add or improve:
- apply same traceability values to selected units
- split line into X equal units helper
- clone unit helper
- batch print labels
- apply same location/freezer/allocation to selected units

9. Keep receipt flow shipment-first
A single receipt should represent one shipment and support multiple receipt_lines from the same PO shipment.
Keep canonical table names already in use.
