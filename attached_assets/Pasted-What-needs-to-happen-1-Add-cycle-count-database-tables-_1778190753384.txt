2. Use the existing ledger for final adjustments

Do not create a separate adjustment history. When a cycle count is approved and posted, write a COUNT_ADJUSTMENT row into inventory_transaction_ledger.

That ledger already supports:

transaction_type
inventory_item_id
lot_id
location_id
quantity_delta
quantity_before
quantity_after
performed_by_user_id
approved_by_user_id
approval_id
reason_code
source_module
source_record_id
event_hash

So for cycle count posting:

transaction_type = COUNT_ADJUSTMENT
source_module = cycle_count
source_record_id = cycle_count_lines.id
quantity_before = expected_qty
quantity_after = counted_qty
quantity_delta = counted_qty - expected_qty
reason_code = CYCLE_COUNT_VARIANCE

7. Add variance thresholds

Start simple:

0% variance = auto pass
Small variance = supervisor review
Large variance = mandatory recount + investigation
High-value material = always approval required
Controlled/prepreg material = mandatory investigation if variance exists
