You are a senior software architect and DCAA-conscious ERP/timekeeping systems auditor.

READ-ONLY AUDIT ONLY. Do not modify files, do not run migrations, do not install packages, and do not make code changes.

Goal:
Audit the current EPOCH codebase to design a salaried employee timesheet/reconciliation system inside the Employee Portal while preserving the existing hourly punch/timeclock system untouched.

Business intent:
We need a salaried timesheet system separate from the hourly punch workflow. Salaried employees should enter/certify 100% of actual total hours worked each week, including direct labor, indirect labor, PTO/leave, holidays, and comp-time-related overtime. The system should ingest traveler/punch-style direct labor capture where available, but employees must be able to reconcile gaps, split time freely across codes, edit imported/captured time with audit trail, and certify weekly.

Key requirements to audit for:

1. Current timekeeping architecture
- Locate all existing timekeeping, punch, employee portal, payroll, PTO, traveler labor, work order, and attendance/presence-board code.
- Identify frontend routes/components, backend routes/services, database tables, schemas, API endpoints, permissions, and shared utilities.
- Determine how hourly punch in/out currently works.
- Determine how current In/Out Board, Clocked In Now, and Active Employees cards derive their data.
- Preserve current hourly behavior.

2. Employee Portal fit
- Find where salaried users currently access employee-facing features.
- Identify the safest place to add a salaried “Timesheet” module.
- Determine whether user roles/employment type already distinguish hourly vs salaried.
- Identify permission/capability patterns for HR, Payroll, Upper Management, supervisors, and executives.

3. Traveler/direct labor ingestion
- Find all traveler/work order/labor capture logic.
- Determine whether travelers already create punch-like records, labor events, job transactions, operation start/stop events, or employee activity logs.
- Identify how these can become imported salaried timesheet source entries.
- Determine whether source entries can be linked to traveler, work order, contract, project, customer, operation, and employee.
- Identify any risks where traveler labor is currently tightly coupled to hourly punches.

4. Salaried timesheet model
Evaluate what schema/API/frontend changes would be needed for:
- Weekly timesheet periods.
- Daily line items.
- Actual total hours worked, not fixed 8-hour assumptions.
- 100% weekly accounting requirement.
- Direct labor lines.
- Indirect labor dropdown lines.
- PTO/leave lines imported from existing PTO workflow.
- Automatic holiday lines from company holiday calendar.
- Comp time earned/used/borrowed balances.
- Manual direct labor against approved parent project/contract when no traveler exists.
- Free splitting of days across many direct and indirect codes.
- Optional notes.
- Weekly employee certification.
- Executive lighter exception path.
- Supervisor/HR/Payroll/Upper Management review capabilities.
- HR/Payroll/Upper Management adjustment authority.
- Formal reopen/correction workflow.
- Audit log for every change.
